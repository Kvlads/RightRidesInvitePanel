
# RightRides Event Manager

Полностековое веб-приложение для регистрации участников на автомобильные мероприятия с интегрированной системой голосования администраторов через ВКонтакте-бота и автоматическими Email-уведомлениями.

## AI-Assisted Development (Подход к разработке)

Этот проект создан с использованием современных подходов Prompt-Driven Development. Я выступал в роли **системного архитектора и ведущего разработчика**, а LLM использовалась как продвинутый инструмент (в формате "вопрос-ответ", а не автопилота/агента) для:

* Написания boilerplate-кода и рутинных компонентов.
* Точечного решения узкоспециализированных проблем (например, исправление EXIF-ориентации фотографий при сжатии через `sharp`, настройка DKIM/SPF политик для SMTP).
* Безопасного рефакторинга при смене архитектуры (переход от зависимого VK Mini App к независимому веб-приложению с собственной JWT-авторизацией и Яндекс.Капчей).

## Технологический стек

* **Frontend:** React, TypeScript, Vite, VKUI (для консистентного и привычного мобильного интерфейса).
* **Backend:** Node.js, Express, TypeScript.
* **База данных:** PostgreSQL, Prisma ORM.
* **Бот-интеграция:** `vk-io` (Long Polling, интерактивные клавиатуры).
* **Инфраструктура:** Docker, Docker Compose, Nginx (с пробросом портов и SSL).
* **Дополнительно:** Yandex SmartCaptcha (защита от спама), Nodemailer (SMTP рассылки с HTML-шаблонами), Sharp (конвертация в WebP, ресайз и нормализация EXIF-метаданных).

## Ключевой функционал

1. **Модуль регистрации (Публичный):** Умная форма с валидацией, разделением логики "Участник/Гость", загрузкой до 5 фотографий с превью и невидимой защитой Yandex SmartCaptcha.
2. **Модуль модерации (Бот):** Все заявки падают в чат администраторов ВК. Реализована система Inline-голосования (одобрение при >70% голосов "За").
3. **Модуль уведомлений:** Асинхронная отправка кастомных HTML-писем участникам по результатам голосования (одобрено/отклонено).
4. **Панель управления (Приватная):** JWT-авторизация администратора, CRUD-операции над мероприятиями, экспорт базы участников.

## Руководство разработчика

### Подготовка и запуск базы данных (Dev)

Для локальной разработки можно поднять только контейнер с БД:

```bash
docker-compose up -d db
```

### Выполнение миграций

При изменении схемы Prisma (`schema.prisma`) необходимо накатить миграцию:

Bash

```bash
cd api/ && yarn db:migrate --name "migration_name"

```

### Управление данными (Prisma Studio)

Для удобного просмотра и редактирования данных через веб-интерфейс:

Bash

```bash
cd api/ && yarn db:studio

```

### Запуск приложения в Dev-окружении

Потребуется открыть два терминала для параллельного запуска клиента и сервера:

**Терминал 1 (Backend):**

Bash

```bash
cd api && yarn start:dev

```

**Терминал 2 (Frontend):**

Bash

```bash
cd app && yarn start

```

### SSH Туннелирование (Webhooks / Тестирование извне)

Для разработки ботов и API требуется внешний хост. Мы используем SSH-туннель для маршрутизации внешнего трафика (через SSL) на локальный порт Vite:

Bash

```bash
ssh -i ~/.ssh/id_u115_rsa -R 2181:localhost:5173 root@xxxx.example.com

```

## Production развертывание

Приложение полностью контейнеризировано и имеет собственный `nginx` на борту, который раздает статику фронтенда и проксирует API-запросы к Node.js.

Для запуска проекта в Production-режиме:

Bash

```bash
docker-compose up --build -d

```

**Сетевая настройка:**

Контейнер отдает трафик наружу. Для предоставления доступа из сети Интернет и подключения SSL-сертификата достаточно настроить внешний Nginx-прокси (host machine) для проброса порта `8080` на данный контейнер.
